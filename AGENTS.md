# AGENTS.md

## Project

Neon Sandbox Pro (web): an email module editor for HubSpot/HuBL. It is the web port of a Kotlin Multiplatform Android app ("workspace_neon"). Only that app's design docs were carried over (`docs/design/`); no Kotlin code exists here. The UI copy is in French and uses tutoiement. Blocks target both emails and the web: keep the UI copy platform-neutral (no HubSpot mentions).

## Stack

TanStack Start (React 19, file-based routes, `createServerFn`) · Tailwind 4 (theme tokens in `src/styles.css`) · Netlify Database + Drizzle (`drizzle-orm@beta`, `drizzle-orm/netlify-db`) · Netlify AI Gateway with `@google/genai`, model `gemini-3-flash-preview`.

## Architecture

- `src/lib/types.ts`: the **ModuleTree** model. Sections hold `cells` (one block list per column); a block can itself be a `section` (nested card). This tree is the single source of truth and is stored as `jsonb` in the `modules` table.
- `src/lib/hubl.ts`: the heart of the two-way sync.
  - `treeToCode` writes email-safe HTML where every node carries `data-neon="<type>"` plus `data-*` settings.
  - `codeToTree` parses it back with DOMParser (browser only) and sanitizes it (no scripts or `on*` attributes). Content without a marker inside a column becomes a `raw` block, so hand-written HuBL survives.
  - `htmlToBlocks` / `importHtml` convert free HTML/HuBL (no markers) into editable blocks (rules from `<style>` sheets are inlined first, so classic class-based CSS keeps its colours and sizes): headings, text, styled links → buttons, images, rules, layout tables → columns, coloured boxes → cards. `{% … %}` statements and unknown elements stay `raw`. `codeToTree` falls back to `importHtml` when the code has no section marker.
  - `reconcileIds` keeps node ids stable across parses so the selection doesn't get lost.
  - `treeToHubSpot` generates the export: text, button and image content becomes `{{ module.field }}` + `fields.json`.
  - Keep `Preview.tsx` visually aligned with the HTML generated here (same metrics).
- `src/lib/clients.ts`: Litmus-style email client tests, simulated in the browser. `renderForClient` applies each engine's known limits to `page.html` (Outlook Windows reads `<!--[if mso]>` and drops border-radius, max-width, media queries and link padding; Gmail IMAP drops `<style>`; full or partial dark mode; images blocked). `auditModule` lists issues per client with the block concerned. UI: `ClientsDialog`.
- Images: uploaded through `POST /api/images` into Netlify Blobs (store `images`) and served by `/api/images/<key>` with an absolute URL. `src/lib/images.ts` downscales to 1600px and converts formats email clients don't support (WebP, HEIC…) to JPEG; GIFs are kept as-is. Image files can also be dropped onto the preview.
- `src/routes/apercu.$moduleId.tsx`: module preview page (final HTML in a sandboxed `EmailFrame`, desktop/mobile, light/dark). `EmailFrame` also renders the library thumbnails.
- `src/lib/fields.ts`: module fields (simplified design manager). Every heading/text/button/image is a field; an optional `field: { name, label }` on the block overrides the automatic name (`heading_1`…). `collectFields` gives unique names in document order and is used by both the Champs panel and `treeToHubSpot`. Custom definitions round-trip through the code as `data-field` / `data-label`.
- `src/lib/module-fields.ts`: exact fields from existing HuBL code. `bindFields` turns whole-content `{{ module.x }}` placeholders of headings, texts, buttons (`cta_text` + `cta_link.url.href`) and images (`.src`/`.alt`) into blocks with `field` definitions that keep the exact names (`FieldDef.textName/linkName` for buttons, round-tripped as `data-field-text/-link`), using an optional fields.json (`parseFieldsJson`) for labels and defaults. Placeholders left in logic or mixed text are reported as `unbound`. `codeToTree(code, fallback, specs?)` calls it on the import branch (code without markers) and returns `binding`.
- `src/lib/module-agent.ts`: `validateModuleCode` checks a generated module (parse, raw ratio, unbound fields) before it reaches the editor or the library.
- `src/lib/hubl-render.ts`: HuBL interpreter for **previews only** (exports keep the HuBL). `renderHubl` evaluates `{{ }}` (filters, tests, ternary, arithmetic), `{% if/elif/else/unless %}`, `{% for %}`, `{% set %}`; `previewScope` supplies a sample contact (`known`/`unknown`), site settings and the module's own fields (unknown `module.x` shows `[x]`). `interpretTree` resolves the logic across sibling blocks (lone `{% … %}` raw blocks = "logic blocks", `isLogicBlock`; they are hidden, `{% for %}` bodies are unrolled with ids `id~k`) and interpolates every text field except the selected block (so in-place editing keeps the source). `previewEmail` (hubl.ts) = `standaloneEmail(interpretTree(...))`, used by the editor preview, `/apercu`, Clients tests and library thumbnails. Logic blocks don't count as "free code" in `recognizeCode`/`validateModuleCode`.
- File space (`/fichiers`, `src/routes/fichiers.tsx`, `src/lib/files.ts`, `api.files.ts`, `api.files_.$key.ts`): general file storage in Netlify Blobs (store `files`, running total in store `files-meta` key `usage`; no DB table). Whitelisted extensions (no SVG/scripts), 10 MB per file, 200 MB quota, keys `<time base36>-<id>.<ext>` so listing is chronological without reading metadata; the list is paginated (metadata read only for the page) and images load lazily. Served with `nosniff`, `Content-Security-Policy: sandbox`, inline only for images/PDF. `/api/images` stays the image uploader used by blocks. The editor loads `MailyPanel` lazily (`React.lazy`): keep heavy chat dependencies out of the main editor chunk.
- `src/lib/extra-fields.ts` + `syncExtraFields` (hubl.ts) + `ModuleTree.fields`: every `module.<name>` the code uses that no block owns (date, `{% if %}` flag, color, `{% for %}` repeater…) becomes an `ExtraField` (type guessed from usage — `choice` drop-downs only for the countdown address params u=/lang=/st= —, default value for the preview, exported in fields.json). Recomputed on every commit / code edit / Maily apply; user edits to a field are kept. Blocks whose content holds a variable (`holdsVariables`) are exported inline, not as fields; colours may be variables too (kept at import, interpreted in the preview). `sanitize-tree.ts` rebuilds `fields` server-side (`safeJson` for HubSpot values and definitions, nested groups up to depth 4).
- HubSpot import, exact fields (`extra-fields.ts` rewrite): an `Analyzer` builds a usage tree of every `module.`/`widget.` path, follows `{% set alias = module.x %}` and loops at any depth (`for c in module.group.cards` → repeater, item properties typed), reads tags/functions (`{% cta %}`, `{% icon %}`, `{% form %}`, `inline_text`/`inline_rich_text field=…`, `cta()`, `hubdb_table_rows()`…) and literal comparisons (→ `choice` options). `hubspotType` maps property sets to the exact HubSpot types (reference: developers.hubspot.com/docs/cms/reference/fields/module-theme-fields); a key with sub-keys of its own makes a group. `ExtraField.type` is the editor kind (incl. `url`, `file`, `font`, `alignment`, `textalignment`, `backgroundimage`, `json`), `hsType` the exact HubSpot type, `spec` the rest of the fields.json definition (exported as is by `hubspotField`), `keep` = imported, kept even when unused ("Retirer ce champ importé" in Champs). `parseFieldsJson` keeps `raw`; `fromSpec` rebuilds a field exactly; bound block fields keep their definition in `FieldDef.specs` (used by `Ctx.field`). `syncExtraFields(tree, specs, source)` also reads the imported source (references the converter drops, e.g. in styles). `scopeValue` adds HubSpot's `.css` for font/spacing/border/backgroundimage/gradient/alignment in previews; `hubl-render` prints `inline_text`/`inline_rich_text`, placeholders for cta/icon/form/video, `widget` = `module`, module-wide `{% set %}`. Older HuBL (`hubl-legacy.ts`, applied in the `codeToTree` import branch, the analyzer, `extractFieldRefs`, `recognizeCode` and `importSpecs`): `module['x']` → `module.x`, `widget_data.x.value` → `module.x`, legacy template tags (`{% text "x" value=… %}`, `header`, `rich_text`, `raw_html`, `image`, `linked_image`, `image_src`, `boolean`, `choice`, `color`, also inside `{% widget_block %}…{% widget_attribute %}`) → placeholders + field specs (`withLegacySpecs`, given specs win). `bindFields` binds a heading/text only to text/richtext specs (a choice printed in a text stays a variable). A plain value in `href` named like a document → `file`; `.style` on a font-named value → `font`. Bench: 52/52 on a second corpus (inline tags, dict access, HubSpot tags, functions, filters, aliases, deep groups, nested loops, fonts, legacy e-mail tags). Loops over cells (`{% for c in row %}<td width="50%">…</td>{% endfor %}` in a `<tr>`, e.g. after `|batch(2)`) keep their logic around the cell's content and the `for` raw block gets `RawBlock.cols` (2|3 from the td width, `data-cols`): the preview (`interpretTree`) lays the iterations out in rows of `cols` columns (synthetic `id~rowN` sections, blank spare cells), the HubSpot export writes `<table class="neon-stack"><tr>{% for %}<td class="neon-col">…</td>{% endfor %}</tr></table>` (`renderCell`). A paragraph with inline logic opened and closed inside it (`{% for i in range(5) %}★{% endfor %}`, `{% if %}<img width=40>{% endif %}`) stays one text block (`inlineLogic`/`inlineOnly`, small images count as inline); `text-transform` is kept on such paragraphs. Bulletproof buttons take their colour from the cell (`cellBg`, variables allowed) and shrink-wrapped tables don't centre their button. A card table without padding (`flushCard`) keeps its image flush and its padded rows as inner sections; borders of boxes become `borderWidth`/`borderColor`. Colour variables (`{{ … }}`) and `FieldDef.specs` (`data-field-specs`) survive the code round trip. Sections holding only logic (`{% set %}`) are left out of the preview. `hubl-render` filters added: `batch`, `slice`, `map`, `select(attr)`/`reject(attr)`, `sum`, `min`, `max`, `unique`, `sort(attribute=)`, `add`/`multiply`/`divide`…, `escape_url`/`escape_attr`, `tojson`, `regex_replace`, `format_currency_value`…, keyword arguments (`name=value`), tests `lt`/`gt`/`divisibleby`/`within`… Macros: `{% macro %}…{% endmacro %}` definitions are kept whole as one logic block (`parseFragment` marks them, `restoreMacros`), `isMacroBlock` = logic, `interpretTree` defines them module-wide (`defineMacros`) and `renderHubl` runs them (`{{ CTA(u, t) }}`, keyword args). Logic opened before a card and closed after it keeps the whole import in one section (`importHtml` balance check), the `{% for %}`-`{% else %}` detection ignores the `else` of inner `{% if %}`, empty bordered boxes become dividers (dotted/dashed, colour variable, margins), small shrink-wrapped rows (stars + "5/5") one text line, `bgcolor="{{ C }}"` a section colour, `box-shadow` kept on cards, paragraphs keep bold (`font:700`), capitals and their own margins, text blocks whose variables print nothing take no room in the preview, HuBL in text keeps its quotes (`escKeep`). `scopeValue` keeps nested repeaters as lists. `ExtraField.noDefault`: an imported definition without `default` exports none while the value is still the preview stand-in (fields.json byte-identical). Bench: the real M2i "Card formation verticale enrichie" (macros, nested repeaters, compact `{%…%}`) imported with its fields.json and HubSpot preview values renders the same texts, images and links as HubSpot, and exports an identical fields.json. Bench: an M2i card module (repeater of cards in 2 columns, stars, CPF/AC pictos, VML CTA) imported with its fields.json renders the same texts, images and links as the module itself. Import fidelity: `hubl-protect.ts` (comments for tokens between tags so `{% for %}` between `<tr>` stays in place, `data-nsp-t<n>` for statements inside a tag, restored in all strings), `convertTable` keeps row-level statements, `Section.css` keeps HuBL style declarations (`data-css`), unbound content of a HubSpot module is `fixed` (`data-fixed`, not a field; Inspector "Dans le module exporté"), `wholeRef` binds only with text filters. - Structure tab (`Structure.tsx`, state in `TreeCtx`): sections fold/unfold (chevron `aria-expanded`, folded row shows « N éléments · replié »; folded ids remembered per module in localStorage `nsp-folded-<moduleId>` via `storageKey`), « Tout replier » / « Tout déplier », « Suivre » (`nsp-structure-focus`: only the top-level section of the selection stays open), the selection is always revealed (its sections open, row scrolled into view), search field (matching rows and their sections, folding ignored), drag and drop of rows in the tree (`moveNodeTo`: before/after a row, a block dropped on a top-level section goes at the end of its first column; cyan line / ring), keyboard (↑/↓ between rows, →/← unfold/fold a section, F2 rename), section names (`Section.name`, `data-name`, ≤ 40 chars, no `<>{}`; double-click / pencil / F2 in the tree or « Nom (dans la Structure) » in the Inspector; never in the e-mail). Each row = select button + action buttons (no nested interactive elements).
- `src/components/editor/*`: Structure, FieldsPanel (Champs: label, HuBL name and value per field), Preview (headings, texts and button labels are editable in place once selected), Inspector, CodeEditor (transparent textarea over a highlighted `<pre>`), MailyPanel, ExportDialog.
- `src/components/Maily.tsx`: the mascot as an animated SVG with moods `happy | thinking | success`.
- `src/server/modules.functions.ts`: module CRUD (server functions).
- `src/lib/recognize.ts`: code sent to Maily (pasted, typed or attached) is detected (`extractCode`), classified and converted locally with `codeToTree` (`recognizeCode`). If the import is complete it is applied at once and Maily only reviews it (`imported` flag); if it is too lossy (mostly raw blocks, `{{ module.… }}` placeholders) the model recreates it (`issue`). In Conseil mode a plain question about code doesn't replace the module (`wantsConversion`).
- `src/routes/api.maily.ts`: streams the Maily chat (plain text), modes `chat | build`, with optional images (screenshots/mockups, base64) per message. When Maily creates, recreates or edits the module, her answer contains one ` ```neon ` block holding the full module; `MailyPanel` hides it while streaming and applies it with `applyCode` (undoable). Maily is autonomous: ` ```neon new <name> ` creates a module in the library (`createModule`, link "Ouvrir" in the answer) without touching the open one, several blocks per answer are allowed, every block goes through `validateModuleCode` and a refused one is sent back to Maily as a hidden message (2 retries max). The request also carries `fields` (current fields) and `fieldSpecs` (attached fields.json). Attached HTML files and long pasted HTML are sent inline in the message. Maily has the Gemini `googleSearch` and `urlContext` tools (retried without tools if refused); grounding sources are appended as a **Sources** list. `src/routes/api.generate.ts` only handles text rewrites.

Engine 1: Gemini Nano through Chrome/Edge's Prompt API (`window.LanguageModel`, French in/out, images read). Engine 2 (no Prompt API, WebGPU present): Gemma 4 E2B through `@mlc-ai/web-llm` (q4f16, or q4f32 without `shader-f16`; Gemma 3 1B first when `deviceMemory` < 8 or on failure), context 8192, files in the `webllm/*` caches that `sw.js` never deletes (sign-out included); the web-llm chunk is imported dynamically; engine unloaded after 4 idle minutes or when the page is hidden. `MailyPanel.converse` uses it when offline (or when the request fails on the network): same ```neon protocol, `validateModuleCode` + correction loop, modules/blocks created through `createLocalFirst` / `saveBlock` (queued offline). The prompt is `localSystemPrompt` (maily-prompts.ts): same persona, scope, reply and format specs, `OFFLINE_SPEC` instead of `RESEARCH_SPEC`, the open module whole or only an outline (never cut), FIELDS_SPEC when fields are involved and the `APP_GUIDE` lines closest to the question (`guideExcerpt`), all within the window (~3 chars/token). CSP: `wasm-unsafe-eval` + Hugging Face / raw.githubusercontent.com in `connect-src` for the Gemma download.

## Conventions

- Use `@/` imports for `src/`. Server functions use `.validator(zod)` (the API exposed by the pinned `@tanstack/react-start` version; `.inputValidator` does not exist there).
- Never pass an API key to `GoogleGenAI`: AI Gateway injects it.
- Any schema change requires `npx drizzle-kit generate --name …` (migrations go in `netlify/database/migrations`).
- Starter images are referenced by absolute Image CDN URL (`src/lib/templates.ts`) so they keep working in emails exported to HubSpot.
- Security (see `SECURITY.md`): never put user/AI HTML in the DOM or in storage without `sanitizeHtml` (`src/lib/sanitize.ts`, allow-list, keeps HuBL tokens); trees reaching the server go through `sanitizeTree` (`sanitize-tree.ts`, wired in the `treeSchema`/`sectionSchema` transforms) so new block fields must be added there too; `src/start.ts` holds the CSRF check, security headers/CSP and rate limits (`src/server/rate-limit.ts`): a new external origin (script, font, image host) needs a CSP update; uploads must pass `matchesType` (`upload-check.ts`).
- Accounts: Netlify Identity (`@netlify/identity`). Sign-in page `src/routes/connexion.tsx` (browser-side `login`/`signup`), the root route redirects to it, and `src/server/auth.server.ts` (`requireUser` for server functions, `sessionUser`/`unauthorized` for API routes) is the real check on every call. **Every query must be scoped by `user_id`** (modules, custom_blocks) and file keys carry an owner tag (`src/server/file-owner.ts`); never fetch by id alone. Data from before accounts goes to one account via `legacyOwner` (`LEGACY_OWNER_EMAIL`). Locally there is no Identity: run with `NEON_DEV_USER=<id>` (ignored in production). Identity does not work under `netlify dev`; test sign-in on a deploy.
- Standards (W3C): every page and dialog validates with the Nu Html Checker (vnu, the W3C validator) with no error or warning, the built CSS passes `csstree-validator`, and axe-core (WCAG 2.2 AA + best practices) reports nothing on the app's own UI. Keep it that way: no block content (`div`, `p`, headings, iframes) inside `button`/`a` (use spans, or a stretched link/button with `after:absolute after:inset-0` next to an iframe thumbnail); one `<label>` = one control (two controls → `Group` + `aria-label` each, see `ColorField`); `type="button"` on non-submit buttons; `role="tab"` with `aria-controls` to a `role="tabpanel"`; only one `main`/`header` landmark per page (dialogs use `div`); labelled `aside`s; heading levels without gaps (the editor has an `sr-only` `h1`, its panels use `h2`/`h3`); accessible names contain the visible text (prefer `sr-only` text to `aria-label`); white text never on `pink` (3.8:1) but on `pink-fill` (#e0006f, 4.8:1), pink text stays `pink`; icon buttons ≥ 24px; scrollable code areas focusable (`tabIndex=0` + `role="region"`); `env()` inside `max()`. Exported e-mails validate without errors; the remaining warnings (table `width`/`cellpadding`/`cellspacing`/`border`, `td` `valign`) are kept on purpose for Outlook and old webmails. axe flagging the e-mail's own content (a #ff007f button) concerns the user's design, not the app.
- Platform rate limiting lives in `netlify.toml` (`[[redirects]]` + `rate_limit`, max 2 rules on free plans).

- HuBL tags in raw HTML survive the DOM round trip only if: comparison operators are un-escaped (`sanitize.ts` `unescapeOperators`) and no `{% if %}` sits between table cells (the HTML parser moves it out of the table): wrap whole tables in the condition instead.
- Touch / small screens: `styles.css` has, in `@layer base` (so utilities still win), centred icon-only buttons and a `@media (pointer: coarse)` block (≥ 40px for buttons, selects, text inputs, `a[aria-label]`, header links; opt out with `.underline` or `.tap-auto`). Editor header: on phones (< `sm`) it wraps into two rows (name + save + export / undo-redo + VML + Clients + Aperçu); the bottom pane switcher goes icon-left in landscape phones (`max-height:500px`); the VML window is full height there and hides its explanatory text.
